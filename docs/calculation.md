# 计算模型 · Calculation model

本文说明 `packages/calculator` 的全部公式与假设。所有函数都是纯函数、无 I/O，可在
`packages/calculator/src/*.test.ts` 中逐条验证。

---

## 1. 有效充电功率

这是整个引擎最重要的一条规则：

```
有效功率 = min(充电桩功率, 车辆该电流类型上限) × 衰减系数(SOC) × 温度系数
```

**为什么必须钳制。** 家用 7kW 交流桩接一台车载充电机（OBC）只有 6.6kW 的车，实际
功率是 6.6kW。忽略这一点会让每次家充的时长少算 5%~10%。

### 交流（AC）

车载充电机在绝大部分区间恒功率，只在接近满电时进入恒压阶段：

| SOC | 功率系数 |
| --- | --- |
| 0–92% | 1.00 |
| 92%→100% | 线性衰减到 0.25 |

### 直流（DC）

直流的衰减（taper）非常显著，且与电芯化学体系强相关。默认曲线：

| SOC | LFP / LMFP / 钠离子 | NMC / NCA |
| --- | --- | --- |
| 0% | 0.85 | 0.85 |
| 10% | 1.00 | 1.00 |
| 30% | 1.00 | 1.00 |
| 40% | 1.00 | 0.92 |
| 50% | 0.95 | 0.82 |
| 65% | 0.72 | 0.62 |
| 80% | 0.45 | 0.40 |
| 90% | 0.22 | 0.20 |
| 100% | 0.06 | 0.05 |

> LFP 平台期更长但 80% 之后掉得更狠；三元锂衰减更早、更平缓。
> 车型数据可通过 `dcCurve` 字段提供实测曲线覆盖默认值。

### 温度

低温对直流功率影响巨大，对交流则主要体现为效率下降（电池加热耗电）：

| 温度 | 直流功率系数 | 效率系数 |
| --- | --- | --- |
| −20°C | 0.25 | 0.75 |
| −10°C | 0.35 | 0.82 |
| 0°C | 0.55 | 0.90 |
| 10°C | 0.80 | 0.96 |
| 20–35°C | 1.00 | 1.00 |
| 45°C | 0.80 | 0.97 |

## 2. 逐分钟仿真

引擎不是用「总电量 ÷ 功率」一步算出时长，而是按 **1 分钟步长推进**：

```
每一分钟：
  P     = 有效功率(当前 SOC)
  取电   = P × (1/60)                    kWh，电网侧
  入电   = 取电 × 效率                     kWh，进入电池
  ΔSOC  = 入电 ÷ 可用容量 × 100           %
```

最后一步按比例缩短，使结果精确落在目标 SOC 上而不是被取整到整分钟。

**为什么要这么做。** 只有逐分钟推进，才能

1. 正确处理随 SOC 变化的功率衰减；
2. 把每一分钟的取电量落到它真正所处的峰/平/谷时段里，而不是用平均电价糊弄。

## 3. 峰谷电价与费用

### 时段解析

时段用 `HH:mm` 表示，`to <= from` 表示跨零点（例如 `23:00 → 07:00`）。
加载数据时会强制校验：**一天的时段必须不重不漏地覆盖 24 小时**，否则拒绝加载——
否则某段充电会被静默按 0 元计费。

季节、工作日/周末可分别配置。

### 阶梯电价（中国居民电价的真实结构）

月累计用电量越过档位阈值后，每度电加价：

```
单价 = 时段电价 + 阶梯加价(月累计用电量) + 服务费
```

阶梯加价按会话推进中的**运行累计值**取，因此一次跨越档位的充电会被分别按两侧档位
计价，而不是整体套用一个价。

### 费用

```
费用 = Σ(每分钟取电量 × 该分钟单价)
折合单价 = 费用 ÷ 总取电量
```

## 4. 四种充电策略

| 策略 | 行为 | 适用场景 |
| --- | --- | --- |
| `asap` | 插枪即充 | 急用车 |
| `latest` | 反推最晚开始，恰好在出发前 buffer 分钟充满 | 最小化高 SOC 停放 |
| `cheapest` | 在可用窗口内选最便宜时段 | 最省钱 |
| `balanced` | 费用最低，同价时选最晚开始 | 默认推荐 |

### `latest` 为什么不需要搜索

功率只依赖 SOC，不依赖时钟，所以总时长是一个确定值。直接
`开始 = 出发 − buffer − 时长` 即可。开始时间向下取整到整分钟（充电桩没法预约到秒），
因此结束时间会比截止点早不到一分钟——宁可早完成，绝不超时。

### `cheapest`（连续）如何找到最优解

固定时长的充电块，其费用关于开始时间是分段线性的，最优解必定出现在：

- 可用窗口的两端，或
- 块的**开始**对齐某个电价切换点，或
- 块的**结束**对齐某个电价切换点

因此只需检查这十几个候选点，无需逐分钟扫描 720 种可能。

### `cheapest`（分段）的贪心算法

允许分段时：把窗口切成 5 分钟槽 → 按单价排序（同价时靠后优先）→ 取最便宜的 N 个槽 →
**按时间顺序**仿真（因为功率依赖 SOC，顺序不能乱）→ 若未达标则追加下一个便宜槽，
迭代至收敛。

### `balanced` 的取舍

在成本落在最优解 2% 以内的候选中，选**开始最晚**的那个。省同样的钱，但车在高电量
状态下停放的时间更短。

## 5. 与需求文档示例的对照

需求文档给出的算例是：元UP、35% → 85%、7kW、92% 效率、耗时「3小时41分钟」。

用 7kW 直接算是 3h30m，对不上。但代入**元UP 实际 6.6kW 的车载充电机上限**：

```
入电量  = 45.12 kWh × (85% − 35%)        = 22.56 kWh
取电量  = 22.56 ÷ 0.92                    = 24.52 kWh
有效功率 = min(7, 6.6)                     = 6.6 kW
时长    = 24.52 ÷ 6.6                     = 3.715 h = 3小时43分钟
```

与文档的 3h41m 几乎完全吻合——这反过来印证了功率钳制规则的正确性。该算例已固化为
黄金测试用例（`packages/calculator/src/simulate.test.ts`）。

> 文档中另外两个数字（补电 22.8kWh、费用 ¥7.21）彼此不自洽：隐含单价 0.316 元/kWh
> 与常见谷电价不符。本项目不去凑这两个数字，而是保证引擎输出内部自洽的结果。
> 按 0.30 元/kWh 谷电价，同一算例的费用是 **¥7.36**。

## 6. 电池健康

建议按化学体系区分，而不是一刀切：

| | LFP / LMFP / 钠离子 | NMC / NCA |
| --- | --- | --- |
| 日常区间 | 20–90% | 20–80% |
| 长期停放 | 60% | 55% |
| 满充校准 | **建议每 14 天一次** | 基本不需要（60 天） |

**LFP 为什么需要定期满充。** 磷酸铁锂的电压平台非常平坦，BMS 难以通过电压反推 SOC，
时间久了显示会漂移。充满一次可以让 BMS 重新标定。

### 应力评分（0–100，越低越好）

```
应力 = 高SOC暴露(0–35) + 高电量停放时长(0–25) + 温度极端(0–20) + 快充占比(0–20)
```

这是一个用于**横向比较不同充电习惯**的相对指标，不是电池衰减预测。

## 7. 续航估算

```
续航 = (可用电量 ÷ 百公里电耗) × 100 × 温度系数 × 空调系数
```

温度系数：25°C = 1.0，10°C ≈ 0.88，0°C ≈ 0.75，−10°C ≈ 0.65，−20°C ≈ 0.55；
LFP 在 5°C 以下再乘 0.95。空调开启再乘 0.92。

行程反推：

```
所需 SOC = (里程 × 电耗 ÷ 100 ÷ 温度系数) ÷ 可用容量 × 100 + 到达保留电量
```

## 8. 已知简化

诚实列出本模型没有做的事：

- 充电曲线是**分段线性近似**，不是实测曲线（车型可通过 `dcCurve` 提供实测数据）。
- 未建模电池预热的额外能耗，也未建模充电中的电池温升对功率的反向影响。
- 阶梯电价按**月**累计，部分地区实际按年累计。
- 效率取固定值 × 温度系数，未随功率变化（实际低功率时效率略低）。
- 停放自放电未计入 SOC 演化，只体现在停放模式的建议里。
- 车型与电价数据来自公开资料，**标记为待核验**，可能与实际存在差异。
